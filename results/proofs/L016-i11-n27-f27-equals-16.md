## Statement

$C$ is the class of L007–L014: 3-graphs that are (P1) linear, (P2) $F_7$-free ($F_7=\{012,034,056,135,246\}$) and (P3) satisfy $e(S)\le|S|-2$ for every vertex set $S$ with $|S|\ge2$. $\tau$ is the transversal number, $\Delta$ the maximum degree, $s(H)=3n+2m-11\tau(H)$ the I11 slack, and $\mathcal C(n,m,t,D)$ the set of connected $X\in C$ with $n$ vertices, $m$ edges, $\tau(X)=t$ and $\Delta(X)\le D$.

**Theorem 1 (I11 at 27 vertices).** Every $H\in C$ with $n=27$ vertices satisfies $11\,\tau(H)\le3n+2m$. With L013 Theorem 1: every $H\in C$ with at most 27 vertices satisfies $11\,\tau(H)\le3n+2m$.

**Corollary 2.** Every (4,5)-set $A$ with $|A|\le27$ satisfies $11\,\tau(H(A))\le3|A|+2m(A)$ ($m(A)$ = number of 3-term APs in $A$), i.e. $h(A)\ge|A|-\lfloor(3|A|+2m(A))/11\rfloor$.

**Theorem 2.** $f(27)=16$: every 27-point (4,5)-set $A$ has $h(A)\ge16$, and
$C_{27}=A_{\rm base}\cup(10^9+7919\cdot B_{13})$, $B_{13}=A_{\rm base}\setminus\{1056\}$, that is
$C_{27}=\{0,136,200,243,246,249,272,286,298,323,400,528,596,1056,1000000000,1001076984,1001583800,1001924317,1001948074,1001971831,1002153968,1002264834,1002359862,1002557837,1003167600,1004181232,1004719724\}$,
is a 27-point (4,5)-set with $h(C_{27})=16$.

**Corollary 3.** No 27-point (4,5)-set beats $4/7$ (that needs $h\le\lceil108/7\rceil-1=15$). With L011 (no record with $n\le22$, K55), L014 ($n=23$, K58) and K8 ($n=24,26,28$), no (4,5)-set with $n\le24$ or $n\in\{26,27,28\}$ points beats $4/7$. Among $n\le30$ the sizes at which no result used here excludes a set beating $4/7$ are exactly $n=25$ (only the saturated I11-tight cell $(25,23,11)$, L014 Corollary 3), $n=29$ (cells $(29,26,13)$, $(29,27,13)$, K8-feasible, I11 slacks $-4,-2$; I11 at $n=29$ is not proved) and $n=30$ (cells $(30,m,13)$, $24\le m\le28$). (In particular $n=28$ is not a candidate size: K8 excludes it, C1 (c) and `python3 -m e757.fn_bounds`; so after $n=25$ the next sizes not excluded are $29$ and $30$.) Records do exist at larger sizes: the 65-point [community] set C003 with $h=37$ (K59) and the family of K60.

## Proof

### Step 0. Facts used
0.1 (L007–L013 Step 0.1.) $n,m,\tau,s$ are additive over components; a single vertex has $s=3$; $C$ is hereditary (every subhypergraph, in particular $H-v$ and every component, lies in $C$); for $H\in C$: $\tau\le m$, $\tau(H)-1\le\tau(H-v)\le\tau(H)$, $m\le n-2$ for $n\ge2$ ((P3) with $S=V$), $17\tau\le5n+3m$ (K8); a connected 3-graph with $m\ge1$ edges has $n\le2m+1$; deleting a vertex does not increase degrees; a component of a 3-graph is an isolated vertex or has at least 3 vertices.

0.2 (L013 Theorem 1.) Every $H\in C$ with at most 26 vertices has $s(H)\ge0$.

0.3 (Component lemma, L013 0.3, with $N=27$.) By 0.2, every $H\in C$ with 27 vertices and $s(H)<0$ is connected: otherwise every component has at most 26 vertices and slack $\ge0$, and $s(H)$ is their sum.

0.4 (Degree lemma, L013 0.4, with $N=27$.) Let $H\in C$ have 27 vertices, $m$ edges, $\tau(H)=\tau$, $s=s(H)<0$, and let $v$ have degree $d$. $H-v\in C$ has 26 vertices, $m-d$ edges and $\tau'=\tau(H-v)\in\{\tau-1,\tau\}$, and 0.2 gives $0\le3\cdot26+2(m-d)-11\tau'=s-3-2d+11(\tau-\tau')$. If $\tau'=\tau$ this says $s\ge3+2d>0$, false. Hence $\tau(H-v)=\tau-1$ and $d\le\lfloor(s+8)/2\rfloor$ for every vertex $v$.

0.5 (The engine; L013 0.5, Lemma E′.) For a key $(n,m,t,D)$, `engine.cell(n,m,t,D)` writes the list `cell(n,m,t,D)` (file `cell_n_m_t_D<D>.txt` of the cell directory; if the file exists with its INFO line it is loaded instead). **Lemma E′** (L013): *if $n\le31$ and I11 holds on $C$ for all graphs with fewer than $n$ vertices, then every graph of `cell(n,m,t,D)` lies in $\mathcal C(n,m,t,D)$ and every member of $\mathcal C(n,m,t,D)$ is isomorphic to a graph of the list.* Its proof (L013 0.5, L012 3.2–3.4) uses of `ext_d` only the specification of L012 3.5: for an input $G$ on $\{0,\dots,NG-1\}$, `ext_d NG TG T d EP` counts $G$ as `bad_tau` unless $\tau(G)=TG$, and otherwise lists every extension of $G$ by a new vertex $NG$ with $d$ edges $\{NG,a_i,b_i\}$ (pairwise disjoint admissible pairs: not inside an edge of $G$, both ends of $G$-degree $\le EP$) with $\tau\ge T$ that is $F_7$-free and satisfies (P3), each once. Both builds used here satisfy this specification (0.6, 0.7). By 0.2, the hypothesis of Lemma E′ holds for every key with $n\le27$; every key used in this certificate has $n\le27$, and the engine never uses a list with $n'\ge n$ inside a list with $n$ vertices (components of $X-w$ have at most $n-1$ vertices; L013 0.7).

0.6 (Program limits; the build `bin/ext_d` with `MAXP` = 640.) L012's `ext_d.c` has the static bound `#define MAXP 256` on the number $P$ of admissible pairs of one input; the worker's run met inputs with more than 256 admissible pairs (25-vertex inputs of low degree; `ext_d` then stops with exit code 4, which the driver turns into an error). `src/ext_d_maxp640.c` is L012's `ext_d.c` with that one line changed to `#define MAXP 640` (`diff`: one line, C2). In `ext_d.c`, `MAXP` occurs in exactly these places: the capacity of the pair arrays `pa[MAXP]`, `pb[MAXP]`, `pm[MAXP]` (line 28); the size `MAXP/64` of the two forbidden-pair bitsets `fb` (line 156, cleared with `memset(fb, 0, sizeof fb)`) and `fb2` (line 107, `memcpy(fb2, fb, sizeof fb2)`, both of the same size); the allocation of `killb`, `MAXP*(MAXC/64)` words, of which rows $p<P$ and words $w<W\le$ `MAXC/64` are used (line 126); and the test `if (P >= MAXP) { fprintf(stderr, "MAXP\n"); return 4; }` before pair number $P$ is stored (line 153). Every loop over pairs runs over $p<P$, and only bits $p<P$ of `fb`/`fb2` are read or written (`forb_has`, defined in line 91 and used in lines 95 and 111; the update in line 118). Hence, for an input with $P\le256$, the two builds perform the same operations on the same values and print the same lines (and `MAXP/64` is exact in both: $256=4\cdot64$, $640=10\cdot64$); for an input with $P>256$ the 256-build stops with exit code 4 and the 640-build carries out L012 3.5 unchanged. Since the admissible pairs are pairs of vertices of $G$ and $G$ has $NG\le26$ vertices here, $P\le\binom{26}{2}=325<640$: the 640-build never stops with code 4 in this certificate. The other limits (L013 0.6), for $n\le27$: `ext_d` needs $NG\le31$ and $d\le8$ (here $NG\le26$, $d\le3$), at most 262,144 minimum covers per input (exit code 3; the largest number met is 11,259, C3) and at most 40 edges in its edge array (here at most $22+3=25$); `filt` at most 40 edges (exit code 3) and up to 32 vertices (here 27); `canon` $n+m\le64$ (here at most 52); `enum_conn` $N,M\le31$ (direct route only for $m\le10$). Every pipeline of `stream.py` runs under `set -o pipefail` and a non-zero exit code raises an exception; `stream.recurse` raises on `bad_tau`$\ne0$ and asserts `graphs` = inputs = `searched` + `tg_too_small` + `bad_tau` and that the number of HIT lines equals `hits_in_C`. Every run that produced a list used here ended normally.

0.7 (**Lemma B**: the build `bin/ext_d_fast`.) `src/ext_d_fast.c` is `src/ext_d_maxp640.c` with one change (C2, `diff`): when $TG\ge2$, the flag `small` and the array `covers[0..K-1]` are computed by a recursive branching `bcov` instead of the two Gosper loops (which are kept, unchanged, for $TG\le1$); everything else — admissible pairs, the kill search, the $F_7$ pruning, the (P3) test, the output, the counters — is untouched. In L012's code (lines 135–146), `small` $=1$ iff some $(TG-1)$-subset of $\{0,\dots,NG-1\}$ meets every edge of $G$; if `small` $=0$, `covers` lists every $TG$-subset of $\{0,\dots,NG-1\}$ meeting every edge, in increasing order of the bit mask (Gosper's iteration visits the $s$-subsets in increasing numeric order), and the program stops with exit code 3 if there are more than `MAXC` $=262{,}144$ of them. The fast path: `bcov(S, budget, forb, mode)` finds the first edge $e$ (in input order) not met by $S$; if there is none, $S$ is a leaf (mode 0: return 1; mode 1: store $S$ in `covers`, after checking $|S|=TG$ (else exit code 5) and $K<$ `MAXC` (else exit code 3)); otherwise, if budget $>0$, it branches over the vertices $v$ of $e$ not in `forb`, in increasing order, calling `bcov(S∪{v}, budget−1, forb ∪ {earlier branch vertices of e}, mode)`. `small` := `bcov(∅, TG−1, ∅, 0)`; if `small` $=0$, `bcov(∅, TG, ∅, 1)`, then `qsort` ascending and a check that no mask occurs twice (else exit code 5).
*Claim.* For every input and every $TG\ge2$ with $TG-1\le NG$, the fast path yields the same `small`, the same `K` and the same array `covers[0..K-1]` as L012's loops, and exit code 3 in exactly the same cases; it never exits with code 5.
*Proof.* (a) Every leaf $S$ of a call with budget $b$ meets every edge and has $|S|\le b$ (each step adds one vertex and lowers the budget by 1). (b) Let $C$ be a set of vertices meeting every edge with $|C|\le b$. At the root $S=\emptyset\subseteq C$ and $\mathrm{forb}\cap C=\emptyset$. At a node with $S\subseteq C$, $\mathrm{forb}\cap C=\emptyset$ that is not a leaf, the first edge $e$ not met by $S$ is met by $C$; so $S\subsetneq C$, the budget $b-|S|$ is positive, and the vertices of $e\cap C$ are branch candidates (they are not in forb); in the branch of the first of them, $v$, the new set $S\cup\{v\}$ is contained in $C$ and the newly forbidden vertices (the candidates before $v$) are not in $C$. Following these branches reaches a leaf $S^*\subseteq C$. (c) Mode 0 returns 1 iff a leaf exists (the search stops at the first leaf; by (b) the path to $S^*$ is followed unless an earlier leaf was found). A $(TG-1)$-subset meeting every edge gives a leaf by (b); conversely a leaf $S$ with $|S|\le TG-1$ can be padded with further vertices to a $(TG-1)$-subset of $\{0,\dots,NG-1\}$ ($TG-1\le NG$) that meets every edge. So `small` is the same. (d) If `small` $=0$, no vertex set of size $\le TG-1$ meets every edge; then every leaf of mode 1 has exactly $TG$ vertices (by (a)), all labels $<NG$, so exit code 5 never occurs and every stored mask is a $TG$-subset meeting every edge. Every $TG$-subset $C$ meeting every edge is reached by (b) at a leaf $S^*\subseteq C$ with $|S^*|=TG=|C|$, i.e. $S^*=C$; and only once: at each node of the path the branches before $v$ add a vertex not in $C$, and the branches after $v$ have $v$ forbidden, so $v$ never enters their sets; hence no other leaf equals $C$. So the stored masks are exactly the $TG$-subsets meeting every edge, each once (the duplicate check never fires), and after `qsort` they are in increasing order, as in L012's array. The number of them exceeds `MAXC` iff the fast path tries to store a $(\mathrm{MAXC}+1)$-th leaf iff L012's loop reaches `K >= MAXC` with one more cover, so exit code 3 occurs for the same inputs. $\square$
For $TG\ge2$ the rest of `main` reads only `small`, `K` and `covers` from this block, so for every input both builds print the same lines and the same SUMMARY; for $TG\le1$ the code is L012's. In this certificate `ext_d_fast` is called with $TG\in\{8,9,10,11\}$ in run F and B2 and with $TG\ge8$ in the checks, and $TG-1\le NG$ always ($NG\ge22$). Hence `ext_d_fast` satisfies the specification of 0.5, and every list computed with it is the list that `bin/ext_d` would compute. The regression tests of C6 confirm this on 4,600 sampled inputs byte for byte, on all 133,804 inputs of L014's top cell (same counters as L014), and on the four heavy cells against the worker's run with the original enumeration (identical lists and identical `ext_d` counters, C8).
