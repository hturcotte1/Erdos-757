# Transversal richness of tight and slack-1 (and slack-2) class-C graphs

Date 2026-10-27. Purpose: find the lemma that would close case (a) of the structure theorem in kb/methods/i11_proof_plan.md (addendum, (H2)):
a minimal counterexample H to I11 with a degree-3 vertex v such that F = H - v is connected has slack(F) <= 1, and no minimum transversal of F
meets all three pairs {a,b}, {c,d}, {e,f} of co-vertices of v, while F + v is again in class C. All statements below are about the stored
class lists only (listed completeness caveats in section "Caveats"); nothing here is a proof.

## Method
- Data: every connected class of slack 3n+2m-11tau in {0,1,2} in the stored canonical cell lists (L012, L013, L014, L016 tarballs and the
  n=27 worker's tarball; `cell(n,m,tau,D)` = connected members of C with max degree <= D). For each (n,m,tau) the list with the largest D
  is used (`collect.py`, `cells.json`). 19 cells, 5,066 classes (one list per (n,m,tau), so no dedup is needed).
- `rich.cpp` (C++, exact integer arithmetic, 1 process, nice 10): for each graph F: all minimum transversals (branch on the first uncovered
  edge with exclusion of earlier branches; all tau-covers, no truncation anywhere); vertices in a minimum transversal; P2 (pairs inside a
  common minimum transversal) by key k(x,y) = d_x + d_y - [x,y share an edge]; coverage of every two disjoint pairs (pair-pair) by one
  minimum transversal ("meets" = contains a or b); and EVERY triple of three pairwise disjoint pairs (unordered, 15*C(n,6) of them, including
  pairs inside an edge). For each triple: coverable by one minimum transversal (bitset AND); linear (no pair inside an edge of F); F7 in F+v
  (structural test: centre + three edges + two more edges, seven distinct vertices; run for every triple that is uncoverable or
  linear+P-ok); e(S) <= |S|-2 for all S of F+v ("P"), done exactly for ALL S through the identity: with S = {v} + S', e(S) = e_F(S') + k where
  k = number of the three pairs inside S'; P fails iff some S' containing two pairs has |S'| - e_F(S') <= 2 (type A) or some S' containing
  all six vertices has |S'| - e_F(S') <= 3 (type B); the minimum of |S'| - e_F(S') over supersets of a given set is read from a
  superset-min transform over all 2^n subsets (`n <= 26`). admissible = linear + F7-free + P.
  `R2` = all six vertices have d_F = 2 (so degree 3 in H); `R1` = all six have d_F >= 2 ((H2): neighbours of v have degree >= 2 in F).
- Cells with m > n-4 (no degree-3 extension in C because S = V(F+v) already violates e(S) <= |S|-2): the triple part is still computed
  (all triples non-admissible) except for (23,21,10), done in transversal-only mode (`RICH_NT=1`; its triples were skipped for time).
- Independent check: `validate.py` re-computes everything for the first classes of 6_3_2, 8_5_3, 9_4_3, 10_7_4, 10_8_4, 12_10_5, 15_11_6 in
  pure Python from `pyverify.py` (L014's verifier: tau, all covers, in_C), including every triple (admissibility via `in_C(F+v)` for each
  triple, hence also checking the A/B identity); all assertions pass (`validate_output.txt`; the earlier run of the first version for
  10_7_4, 12_10_5 and 15_11_6 also passed). `f7_roles.py` (Python) analyses the F7 copies of uncoverable triples.
- Commands (from this directory): `bash extract.sh; python3 collect.py; g++ -O2 -o rich rich.cpp; g++ -O2 -o rich_nt rich.cpp;
  bash run_all.sh` (then `RICH_NT=1 ./rich_nt < inputs/cell_23_21_10.txt > outputs/cell_23_21_10.jsonl`); `python3 aggregate.py;
  python3 make_tables.py; python3 validate.py <cell> <K>; python3 f7_roles.py <cell> <K>`. Total CPU about 1 hour on a loaded machine.
  (`run_all.sh` skips cells whose output exists; a placeholder file was used to postpone (23,21,10).)

## Observed patterns ([verified-here] = exact statements about the stored lists only; [conjecture] = generalisation)

Throughout, "slack<=1 with m<=n-4" means the cells (17,13,7) [slack 0], (15,11,6), (22,17,9), (26,22,11) [slack 1]; they are the only
cells of slack <= 1 in the lists where a degree-3 extension F+v can lie in C (the others have m > n-4, and for them every triple violates P).

1. [verified-here] Lemma U'' on the data: in all 5,066 classes (slack 0, 1, 2; lists as stored) every vertex lies in a minimum transversal
   (0 exceptions); no enumeration was truncated.
2. [verified-here] P2: pairs {x,y} that lie in no common minimum transversal exist, but only with key k = d_x + d_y - [share an edge] <= 3
   (Table 1, last-but-one column; Table 4). No failure ever has k above floor((s+5)/2) (slack 0: k <= 2; slack 1 and 2: k <= 3), which is
   what I11 on F-x-y forces (so this is a consistency check, not new). The failure rate at the bound is high but not 100%: slack 0: key 1 3/3,
   key 2 14/16, key >= 3 0/2026; slack 1: key 2 1963/2054, key 3 547/20494 (2.7%), key >= 4 0/369,212; slack 2: key 1 463/463, key 2 2931/3807,
   key 3 2197/53369. In the larger tight cells P2 holds for every pair: (17,13,7), (26,22,11) have no P2 failure at all (all pairs have
   k >= 3 there; in (26,22,11) all 36 classes have one degree sequence, Delta = 3).
3. [verified-here] Pair-pair coverage: for every two disjoint pairs {a,b}, {c,d} of F there is a minimum transversal meeting both, in every
   class of every cell, with a single exception, the 3-edge graph (6,3,2) (slack 2, 42/45 pairs of disjoint pairs covered). This holds for
   pairs inside an edge as well. So in slack <= 1 the only way to be uncoverable is the genuine three-pair obstruction.
4. [verified-here] Triple coverage for slack <= 1: in the four cells with m <= n-4, 0 of 393,178 + 695,668 + 49,891,889 + 51,279,372
   (= 102,260,107) admissible triples (F+v in C) is uncoverable; the same holds for the restricted families R2 and R1 (the neighbours of v
   have degree >= 2 in F, and degree exactly 2 for Delta(H) <= 3). The margin is not thin: the smallest number of minimum transversals that
   meet an admissible triple is 17 (of ~360) at (17,13,7), 4 (of 136..177) at (15,11,6), 49 (of 1617..2181) at (22,17,9), 336 (of
   6566..7102) at (26,22,11); fraction at least 2.4% of all minimum transversals. (This is the expected consequence of the empty violator
   cells; here confirmed class by class.)
5. [verified-here] Every UNCOVERABLE triple in a slack <= 1 cell is non-admissible, and which hypothesis kills it is very uniform:
   - in the four cells with m <= n-4 every uncoverable triple that is linear contains an F7 in F+v AND violates e(S) <= |S|-2 (always type B:
     a set S' containing all six vertices with |S'| - e_F(S') <= 3, smallest |S| = |S'|+1 = 8 in 24/24, 380/380, 144/144 cases, 8 or 9 at
     (15,11,6)); the other uncoverable triples have a pair inside an edge (non-linear). Hence on this data "linear + F7-free" alone already
     implies coverable, and so does "linear + e(S) <= |S|-2" alone; and no linear, F7-free, P-satisfying uncoverable triple exists.
   - the F7 copies: each uncoverable linear triple creates 3 copies in (17,13,7) and (22,17,9) (1 or 3 in (15,11,6)); each copy uses 2 or 3 of
     the three new edges (`f7_roles_output.txt`, first classes only, Python). The six vertices lie in a 7- or 8-set S' of F with 4 or 5 edges.
   - in the cells with m > n-4 the uncoverable triples violate P (types A and B) and often also linearity or F7; these are not informative.
6. [verified-here] Slack 2 is different: admissible uncoverable triples exist (these give a tight H with slack 0, no contradiction): (9,4,3): 32 of 360;
   (13,9,5): 61 in 19 of 84 classes; (16,10,6): 28 in 5 of 16; (20,15,8): 56 in 20 of 953 classes; none in (23,16,9) (178 classes).
   (Slack-2 lists are Delta <= 3 only.) So any proof must use slack <= 1, i.e. use the equality tau(H-v) = tau(H)-1 and I11 for the
   components, not a property of C alone.
7. [verified-here] Degree-3 extension needs m <= n-4: the slack <= 1 cells in the lists with m <= n-4 are exactly the four above (cells
   (19,16,8), (23,21,10), (12,10,5), (14,12,6), (10,7,4), (8,5,3) have n-m <= 3). The graphs in these cells are very regular: (17,13,7): 6
   classes, one degree sequence (5 vertices of degree 3, 12 of degree 2); (26,22,11): 36 classes, one degree sequence.

Conjectures suggested by the data (NOT proved; all [conjecture]):
- (C1) If F in C has slack <= 1 and v extends F inside C (three disjoint pairs, F+v linear, F7-free, e(S) <= |S|-2), then some minimum
  transversal of F meets the three pairs. Evidence: items 4, 5. A proof must use slack <= 1: item 6 shows it is false for slack 2.
- (C2) Stronger form: for slack <= 1, three disjoint pairs, none inside an edge of F, are uncoverable only if F+v contains an F7 whose edges
  include at least two of the new edges (and then e(S) > |S|-2 for some S of size 8). Evidence: items 3, 5 (only first classes were
  checked for the "at least two new edges" part).
- (C3) For slack <= 1, any two disjoint pairs are covered by one minimum transversal (item 3), so only the third pair is at stake: it suffices to
  show that, for fixed {a,b},{c,d}, the minimum transversals meeting both do not all avoid {e,f}.
- The "wall" (item 2): P2 fails only when k <= floor((s+5)/2); the failing pairs are exactly those with very low degree weight.

## Caveats
- Class lists are complete only for the degree bound they were computed with: slack 0 and 1 allow Delta <= 4 (floor((s+8)/2)); the stored
  lists have D = 4 for all slack <= 1 cells except (17,13,7) and (26,22,11) (D = 3: degree-4 members NOT included) and (23,21,10) (D = 4, 699
  classes, no Delta <= 3 member). Slack 2 allows Delta <= 5; all slack-2 lists are D = 3 only. A minimal counterexample in (H) has
  Delta <= 3, so the D = 3 columns are the relevant ones; classes with Delta <= 3 are the numbers in parentheses in Table 1.
- Only n <= 26 is covered (the stored lists); the statements do not say anything for larger F, where case (a) of the structure theorem is
  not excluded by these lists.
- (23,21,10): the triple computation was skipped (m > n-4, so no extension exists in C); only the transversal/pair statistics are given.
- Pair counts "admissible" etc. count triples of pairs per labelled graph (not up to automorphism), summed over classes.
- Time: P2/F7/P3 computed by compiled code; independent Python validation covers the first classes of 7 cells (largest n = 15); the n = 17..26
  runs rest on the C++ code with the same logic.
