# (Red) census at n = 15, dense range m = 11, 12, 13 (and, as by-products, m = 7..10) (2026-10-27)

Question. Extend the reducibility census of `../20261027-0230-red-config/` (connected members of C = linear, F7-free, e(S) <= |S|-2,
with maximum degree Delta <= 3, up to isomorphism; (Red) pair (Z,T): `value(Z) = 3|Z| + 2e(Z) - 11 tau(E_Z) >= 0`, definitions and Lemmas R, L
of that README) from n <= 14 to n = 15. Is every class (Red)-reducible (Conjecture RU), what is the smallest |Z| of a reduction, and how large can it get?

## Method [all integer arithmetic]
* **Generation** (`gen15.sh`, `bin/extend2` = `extend2.c`, run by `run_chain.sh`). Same level-by-level scheme as the n <= 14 census: every class of the cell (15,m) arises
  from a class of (15,m-1), (14,m-1) or (13,m-1) by adding one edge with 0, 1 or 2 new vertices. Then nauty canonical form (`../prover/L012/bin/canon`) and `sort -u`.
  `extend2.c` differs from the 0230 `extend.c` only in the ORDER of two tests: the cheap canonical-deletion key filter (edge key = number of private vertices, degrees, neighbour degrees,
  computed without the removability test; removability tested only for edges whose key exceeds that of the new edge) is applied BEFORE the expensive C-membership test
  (linearity, F7, Hall form of e(S) <= |S|-2). Same acceptance set, 3.7x faster.
* **Completeness argument.** (i) C and "Delta <= 3" are closed under deleting edges (and then vertices). (ii) A connected 3-graph with m >= 2 edges has a removable edge
  (delete it together with its private = degree-1 vertices, the rest stays connected; e.g. the last edge of a BFS edge order); it has 0, 1 or 2 private vertices (3 would disconnect it).
  The parent is a connected member of C with Delta <= 3 in the cell (n-k, m-1), k = number of private vertices. (iii) Canonical-deletion filter: among removable edges take one of maximal
  isomorphism-invariant key; the child is produced from a labelled copy of its parent by adding an edge of that key, so it passes the filter (the filter only removes duplicates; header of `extend2.c`).
  So cell (15,m) is complete provided (15,m-1), (14,m-1), (13,m-1) are. The cells with n <= 14 are the 0230 census (inductively generated by the same argument; its own validation is in its README);
  the n = 15 cells were generated in the order m = 7, ..., 13 (each from complete lower cells). (15,13) was streamed and not stored (it is not a parent of anything we generate).
  For m = 7 no (15,6) etc. exist (n <= 2m+1 forces m >= 7), so (15,7) comes from (13,6) only.
* **(Red) test** (`redmin.c`): for each class, the table tau(F) of all 2^m edge subsets (tau(F) = 1 + min over the 3 vertices of the lowest edge of tau(F minus the edges at that vertex)), then all proper
  nonempty vertex sets Z in order of increasing |Z| (Gosper), E_Z = OR of the edge sets at Z; stop at the first size where value(Z) >= 0. This is exact: minsz = min |Z| over all (Red) Z
  (by Lemma L the minimum Z is automatically R-connected). If no Z works the class is (Red)-free. Slack = 3n + 2m - 11 tau. (This is the same value test as `../20261027-0230-red-config/redfree.c`.)

## Validation [verified-here]
* `extend2` vs `extend`: (13,11) regenerated from (13,10),(12,10) byte-identical (md5) and 3.7x faster; `gen15.sh` regenerates the 0230 cells (14,8), (14,9), (14,10), (14,11) byte-identical to the stored `cls_14_*.txt`.
* `redmin` vs `redfree` (0230): joint histogram (min|Z|, slack) identical on the whole of (13,10), (13,11), (14,10), (14,11) (compared with column 14 and column 4 of the old tsv files); first 30000 classes of (14,12) identical too.
* Independent class counts (L012 tools `enum_conn 15 m 0 3 1 | filt FOUND 15 notau | canon | sort -u`, connected survivors): (15,7) = 31, (15,8) = 1047, (15,9) = 20320 - all equal to our counts
  (`indep_15_9.txt`: 20320, 10.5 min). (15,10..13) are NOT independently recounted.
* Filter soundness check: 3119 random parents of (15,11) (every 700th) and 58902-child sample from every 250th (14,11) parent, extended WITHOUT the canonical-deletion filter (`extend2 ... nofilter`): all 198,539 distinct
  children are in the generated (15,12) list (0 missing, `comm`).
* Sanity: minimum slack over all 29,078,965 classes is 1 >= 0 (no violation of I11, as expected from L007-L016).

1. **No (Red)-free class at n = 15** in (15,m), m = 7..13: all 29,078,965 classes have a (Red) pair. So Conjecture RU (every connected Delta <= 3 member of C other than the single AP has a proper (Red) pair)
   holds for n = 15 in the whole range tested (all m, since m < 7 is impossible for n = 15 and m <= 13). Together with the n <= 14 census: the minimal counterexample to I11 has n >= 16 (no new information beyond L007-L016, which already give n >= 28).
2. **Max over classes of min|Z|:** 9 in the requested range (m = 11: 7 classes, slack 12; all have 2-3 pendant vertices); 8 at m = 12 (11 classes, slack 3) and m = 13 (44 classes, slack 5).
   It exceeds the n <= 14 bound of 9 only through ONE class of the extra cell (15,10) (min|Z| = 10, slack 10, tau 5, degrees 1^3 2^12; the 13 other (15,10) classes with tau 5 and slack 10 have min|Z| = 7... one is 10). The bound 9 is not exceeded in m in {11,12,13}.
3. **Slack <= 5 classes needing |Z| >= 7: 64** (all with tau = 6, i.e. exactly the tight-ish ones): (15,12) slack 3: 18 classes (min|Z| = 7: 7, = 8: 11); (15,13) slack 5: 46 classes (min|Z| = 7: 2, = 8: 44). None at m = 11 (its |Z| >= 7 classes have slack 12) and none at m <= 10.
   All 64 have 2 or 3 pendant (degree-1) vertices (degree histograms 1^2 2^8 3^5, 1^3 2^6 3^6, 1^2 2^5 3^8, 1^3 2^3 3^9). Saved in `graphs/n15_minZ_ge7.tsv.gz` (columns m, tau, slack, min|Z|, graph; all slacks, 92 classes);
   the slack <= 5 subset is those rows with slack <= 5. Also `graphs/n15_minZ_ge6.tsv.gz` (6,817 classes) and `graphs/n15_minZ_ge6_slack_le5.tsv.gz` (4,048 classes).
   Slack <= 5 classes with min|Z| >= 6 by cell: (15,12): 18+73 = 91 (min|Z|=6: 73), (15,13): 3,911 + 46 = 3,957.
4. Compare n = 14 (README of 0230): slack <= 5 with min|Z| >= 6 had 8+8 graphs at n = 11..13 and none at n = 14; at n = 15 they reappear in large numbers (4,048). The count of Red_k-free classes for small k keeps growing with n (the
   (Red) pair for the tight graphs becomes non-local: min|Z| = 8 for 44 of the 46 slack-5 hard (15,13) classes), so "reducible with |Z| <= 5" is false already at n = 14 and "|Z| <= 9" is the largest bound seen (n <= 15, m in {11,12,13}).
   This is evidence that a proof of RU by a fixed finite list of small configurations is unlikely; Z of size about n/2 is needed for the slack-3/5 sparse-pendant classes.

## Caveats
* The n <= 14 parent cells are those of the 0230 census; their completeness is as argued/validated there ((14,12), (14,11) etc. rest on the generator, validated against independent tools only for the cells listed in that README).
  The n = 15 cells (15,7..9) are independently recounted, (15,10..13) are not.
* Hash-free exact dedup (nauty canonical lines + sort -u); tau by exact DP; no floating point.
* Counts of classes: the 1.6e7 forecast for (15,13) was low; the exact figure is 17,126,146.
